# Obsidian ↔ Anki Two-Way Sync Plugin Specification

## Goal

Build an Obsidian plugin that provides reliable two-way synchronization between Obsidian markdown notes and Anki cards.

Requirements:

* Bidirectional sync
* Obsidian is source of truth during conflicts
* Sync on startup
* Manual sync via status bar button
* Automatic card discovery
* Automatic card creation
* Automatic file creation from Anki cards
* User-provided ID required (blocks without `id:` are silently skipped)
* Vault mapped to a single configurable root deck (1 vault → 1 root deck, hierarchy preserved)
* Deletion sync both directions
* MVP supports Basic note type only

# Root Deck Mapping

The entire vault maps to a single configurable root deck, with the vault's folder hierarchy preserved as subdecks.

Rule:

* The root deck name is configured in plugin settings (default: vault name if left empty)
* Each file's path is translated to a deck path: `{rootDeck}::{subfolder}::...::{filename}` (`.md` extension stripped, `/` replaced with `::`)
  * Example: `Frontend/JS/Closures.md` with root deck `Obsidian` → deck `Obsidian::Frontend::JS::Closures`
* The deck path is assigned when the card is first created in Anki
* Moving/renaming files in the vault does NOT migrate the card to a new deck — the original deck is preserved

# Card Format

Card blocks are fenced blocks with backtick fences.

Opening fence: 4 backticks followed by `anki` (e.g. ````anki)
Closing fence: same number of backticks as the opening fence (e.g. ````)

Using 4 backticks allows nesting code blocks inside cards without conflicts.
3-backtick fences (` ``` `) are not treated as anki cards — they are regular code blocks.

Example with 4-backtick fence:

````anki
id: 8b2c9d11-58f2-49a4-9cb9-53b0f73df887
ankiNoteId: 1839281

[front]

What is a closure?

Explain lexical scope.

[/front]

[back]

A closure remembers variables from outer scope.

[/back]
````

Rules:

* Multiple cards per file allowed
* Front and back are multiline
* Blank lines preserved
* Markdown preserved
* Code blocks preserved (use 3 backticks inside the card)
* `id:` field is required — blocks without it are silently skipped by the parser
* Plugin writes `ankiNoteId:` into the block after creating the note in Anki

# Identity Model

Primary identity:

```text
id
```

External identity:

```text
ankiNoteId
```

Rules:

```text
id: generated by plugin never changes
ankiNoteId: returned from Anki can be regenerated if needed
```

Why two IDs?

```text
UUID (id):
  stable identity, stored in both systems
  survives delete/re-create cycles
  never changes

ankiNoteId:
  cached foreign key for fast API calls
  avoids looking up UUID in Anki every sync
  can be regenerated if stale
```

Store IDs in BOTH systems.

# Anki Note Type

Create custom note type:

```text
Basic-Obsidian
```

Fields:

```text
Front
Back
UUID
```

Field mapping:

```text
Front  -> [front]
Back   -> [back]
UUID   -> id
```

Why custom note type?

```text
Basic only has Front + Back fields.
Basic-Obsidian adds a UUID field so the plugin can:

  - recover identity after state.json loss
    (re-scan Anki notes, match by UUID)
  - look up notes without cached ankiNoteId
    (query AnkiConnect by UUID field)
```

Do not use tags for identity.

# Conflict Rules

Obsidian wins.

Logic:

```text
if obsidianChangedAfterSync:

    overwrite Anki

else if ankiChangedAfterSync:

    update Obsidian
```

Never allow Anki to overwrite newer Obsidian content.

# Card Creation Flow

## Obsidian → Anki

User writes a card block with `id:`:

````markdown
```anki
id: 8b2c9d11-58f2-49a4-9cb9-53b0f73df887

[front]
Question
[/front]

[back]
Answer
[/back]
```
````

Blocks without `id:` are silently skipped by the parser.

Flow:

```text
parseCards → uuid present
↓
sync() → uuid not in state → createNote action
↓
findNotes(uuid) → identity recovery (no duplicate if state was lost)
↓
ensureDeck + ensureModel + createNote
↓
inject ankiNoteId into block via replaceBlock
↓
save mapping { ankiNoteId, path, lastSync }
```

Result — plugin writes `ankiNoteId:` into the block:

````markdown
```anki
id: 8b2c9d11-58f2-49a4-9cb9-53b0f73df887
ankiNoteId: 12345

[front]
Question
[/front]

[back]
Answer
[/back]
```
````

---

## Anki → Obsidian

Flow:

```text
find note
↓
read file path from local state
↓
create file if missing
↓
append card block
```

File path is stored in the local mapping state, not derived from deck name.

# Out Of Scope (MVP)

Not supported:

* Images
* Attachments
* Cloze cards
* Image occlusion
* Tags
* Extra metadata
* Multi-vault support
* Shared vault sync
* Mobile support
* Rich media
* Background polling / auto-sync timer
* File save watchers (auto-sync on save)

---

# Reliability Requirements

Must handle:

* duplicate sync events
* plugin restart
* Anki closed
* network failure
* malformed blocks
* partial sync failures

Requirements:

```text
sync operations idempotent
```

Never create duplicates from repeated sync.
