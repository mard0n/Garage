# Obsidian ↔ Anki Two-Way Sync Plugin Specification

## Goal

Build an Obsidian plugin that provides reliable two-way synchronization between Obsidian markdown notes and Anki cards.

Requirements:

* Bidirectional sync
* Obsidian is source of truth during conflicts
* Sync on startup
* Sync every 5 mins in background
* Sync on a button press on Obsidian Status bar
* Automatic card discovery
* Automatic card creation
* Automatic folder/deck mapping
* Automatic file creation from Anki cards
* Automatic ID generation
* Automatic deck migration on rename/move
* Deletion sync both directions
* MVP supports Basic note type only

# Folder → Deck Mapping

Mapping rule:

```text
Vault Path:

Frontend/Javascript/Functions.md

↓

Anki Deck:

Frontend::Javascript::Functions
```

Rules:

* Folder separators become `::`
* Filename without extension becomes final deck segment
* Renaming file/folder moves cards automatically
* Moving file moves cards automatically
* A configurable base path determines the root folder for deck mapping
  * Files outside the base path produce no cards
  * Example: base path `Flashcards/` + file `Flashcards/Frontend/JS/Functions.md`
    → deck `Frontend::JS::Functions`

Examples:

```text
Backend/SQL/Joins.md
↓

Backend::SQL::Joins
```

# Card Format

Card blocks are fenced blocks with backtick fences.

Opening fence: 4 backticks followed by `anki` (e.g. ````anki)
Closing fence: 4 backticks as the opening fence (e.g. ````)

Using 4 backticks allows nesting code blocks inside cards without conflicts.
3-backtick fences (` ``` `) are not treated as anki cards — they are regular code blocks.

Example with 4-backtick fence:

````anki
id: 8b2c9d11-58f2-49a4-9cb9-53b0f73df887
ankiNoteId: 1839281

[front]

What is a closure?

Explain lexical scope.

[/front]

[back]

A closure remembers variables from outer scope.

[/back]
````

Rules:

* Multiple cards per file allowed
* Front and back are multiline
* Blank lines preserved
* Markdown preserved
* Code blocks preserved (use a higher backtick count)
* Metadata required after first sync
* Plugin inserts metadata automatically

# Identity Model

Primary identity:

```text
id
```

External identity:

```text
ankiNoteId
```

Rules:

```text
id: generated by plugin never changes
ankiNoteId: returned from Anki can be regenerated if needed
```

Why two IDs?

```text
UUID (id):
  stable identity, stored in both systems
  survives delete/re-create cycles
  never changes

ankiNoteId:
  cached foreign key for fast API calls
  avoids looking up UUID in Anki every sync
  can be regenerated if stale
```

Store IDs in BOTH systems.

# Anki Note Type

Create custom note type:

```text
Basic-Obsidian
```

Fields:

```text
Front
Back
UUID
```

Field mapping:

```text
Front  -> [front]
Back   -> [back]
UUID   -> id
```

Why custom note type?

```text
Basic only has Front + Back fields.
Basic-Obsidian adds a UUID field so the plugin can:

  - recover identity after state.json loss
    (re-scan Anki notes, match by UUID)
  - look up notes without cached ankiNoteId
    (query AnkiConnect by UUID field)
```

Do not use tags for identity.

# Conflict Rules

Obsidian wins.

Logic:

```text
if obsidianChangedAfterSync:

    overwrite Anki

else if ankiChangedAfterSync:

    update Obsidian
```

Never allow Anki to overwrite newer Obsidian content.

## Obsidian → Anki

User writes:

````markdown
```anki

[/front]

[back]

[/back]
```
````

Flow:

```text

↓

↓

↓

↓

[front]

[/front]

[back]
Answer
[/back]
```
````

# Rename / Move Handling

Detect:

```text
file rename
folder rename
file move
```

Behavior:

```text
recalculate deck path
↓
move Anki notes to new deck
```

Deck path is derived dynamically.

Never store deck path in card.

↓

↓
remove mapping
```

## Anki Delete

Card removed from Anki:

```text
detect UUID disappeared
↓

↓

* Images

* Cloze cards
* Image occlusion
* Tags

# Reliability Requirements

Must handle:

* duplicate sync events
* plugin restart
* Anki closed
* network failure
* malformed blocks
* partial sync failures

Requirements:

```text
sync operations idempotent
```

Never create duplicates from repeated sync.
